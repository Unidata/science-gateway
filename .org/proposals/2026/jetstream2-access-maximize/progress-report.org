* Executive Summary

:END:

- Supported atmospheric science education by providing customized PyAOS JupyterHub environments on Jetstream2 to 430 students across 12 universities and workshops.
- Expanded educational capabilities by integrating browser-based streaming desktops for IDV and AWIPS CAVE, enabling cloud-based analysis and visualization workflows without local software installation.
- Continued operation of the public AWIPS EDEX server on Jetstream2, serving up to 300 daily users, while supporting classroom instruction and the 2026 AMS Student Workshop.
- Migrated NSF Unidata's JupyterHub infrastructure from Kubespray/Terraform/Ansible to OpenStack Magnum, enabling autoscaling Kubernetes clusters that improve resource utilization.
- Deployed 19 production Magnum clusters (plus additional test clusters), gaining experience that led to numerous improvements benefiting both NSF Unidata and Jetstream2 community.
- Collaborated with the Jetstream2 team to improve Magnum reliability, security, and functionality through work on ingress migration, cluster lifecycle management, persistent storage, shared home directories, GPU support, and Dask-enabled deployments.
- Developed a prototype workflow for publishing NOAA MRMS data as cloud-native Zarr/Icechunk datasets on the Jetstream2 object store enabling access through the Unidata THREDDS Data Server, with production deployment planned for the next allocation period.

** PyAOS JupyterHubs
:PROPERTIES:
:CUSTOM_ID: h-E0B9E04B
:END:

NSF Unidata is using its Jetstream2 resource allocation to support atmospheric science education by providing customized PyAOS (Python for Atmosphere and Ocean Science) JupyterHub servers[cite:@Arms2020b]. NSF Unidata staff tailors these cloud-based environments to the instructional requirements of individual university courses, enabling instructors to meet their Earth system science teaching objectives. During the reporting period, NSF Unidata served 430 students at 12 academic institutions and workshops on NSF Unidata JupyterHub servers running on Jetstream2 [cite:@unidatastatus2026].

A notable advancement during the past year has been the integration of streaming cloud desktop technology that provides browser-based access to the Unidata Integrated Data Viewer (IDV) and the Advanced Weather Interactive Processing System (AWIPS) Common AWIPS Visualization Environment (CAVE), the operational weather visualization workstation used by National Weather Service (NWS) forecast offices[cite:@Chastang2025bPaper][cite:@Chastang2025bSlides][cite:@Chastang2026a]. This approach makes sophisticated desktop visualization software available to students without requiring local installation or high-performance hardware. During the fall 2025 semester, Professor Brian Mapes (University of Miami) successfully incorporated the IDV streaming desktop capability into a graduate-level atmospheric science course. Students used a Jupyter notebook to compute wind fields derived from the Global Forecast System (GFS) with WindsPharm, a Python package for atmospheric wind analysis, and wrote the results to netCDF, a self-describing scientific data format developed by Unidata. These results were then visualized in the IDV alongside infrared satellite imagery, all within a single integrated cloud environment. Students performed the complete workflow, from numerical analysis in a Jupyter notebook to interactive visualization in IDV, without leaving the browser.

** AWIPS
:PROPERTIES:
:CUSTOM_ID: h-F26DB5F8
:END:

During this allocation cycle, NSF Unidata continued to host its public AWIPS EDEX server on Jetstream2, providing real-time weather data services to as many as 300 daily users while maintaining separate production and development virtual machines on Jetstream2[cite:@unidatastatus2026]. More than 60 students participated in the 2026 American Meteorological Society Student Workshop where they were introduced to AWIPS for data exploration and visualization. During the fall 2025 semester, the AWIPS team conducted a remote demonstration of AWIPS CAVE for Millersville University. Using the streaming desktop capability described above, students accessed the same operational weather visualization software used by National Weather Service forecast offices directly through their web browsers.

** Kubespray to Magnum Transition
:PROPERTIES:
:CUSTOM_ID: h-CE3BC665
:END:

During this reporting period, the NSF Unidata Science Gateway team transitioned its customized PyAOS JupyterHub deployments to Jetstream2's Magnum service which provides OpenStack-managed Kubernetes clusters with built-in autoscaling. NSF Unidata employs the "JupyterHub with Kubernetes" project to deploy these environments. For the past several years, our Kubernetes clusters had been provisioned with Kubespray, Terraform and Ansible[cite:@Zonca2018a]. Because these clusters had to be sized for peak anticipated demand, computing resources were underutilized during quieter periods such as outside scheduled class times. With Magnum's autoscaling capabilities[cite:@zonca2024magnum], clusters now expand and contract automatically in response to actual usage thereby dramatically improving resource utilization while still supporting peak workloads.

** Jetstream2 Collaboration
:PROPERTIES:
:CUSTOM_ID: h-F7A3F9E0
:END:

Over the course of this work, NSF Unidata deployed 19 OpenStack Magnum clusters, along with additional test clusters to support JupyterHub environments for university courses and workshops. Operating Magnum at this scale has allowed NSF Unidata to gain operational knowledge with the service. This experience has enabled us to identify a number of problems and to work with the Jetstream2 team to improve Magnum for the broader community.

Through this collaboration, the NSF Unidata Science Gateway team helped identify and resolve a number of issues affecting OpenStack Magnum deployments on Jetstream2. These contributions included testing and validating the migration from NGINX ingress controller to Træfik[fn:1], investigating Magnum cluster lifecycle issues[fn:2] (including cluster creation, deletion and persistent volume cleanup), identifying and helping resolve security vulnerabilities[fn:3] [fn:4], adopting a shared NSF home directory architecture based on the 2i2c JupyterHub model[cite:@Zonca2026SharedNFS], and working with Jetstream2 staff to support GPU[fn:5] [fn:6] and Dask-enabled[cite:@Zonca2025DaskOperator] JupyterHub deployments. In sum, these improvements attained through this collaboration have increased the reliability and security of Magnum on Jetstream2.

* Jetstream2 Object Store Experimentation
:PROPERTIES:
:CUSTOM_ID: h-02C59FF2
:END:

Unidata staff developed an experimental workflow for publishing Multi-Radar/Multi-Sensor (MRMS) analysis data as cloud-native Zarr datasets, a chunked storage format designed for cloud object storage and optimized for large multidimensional scientific datasets, backed by Icechunk, a versioned storage layer for Zarr data, and hosted on the Jetstream2 object store. The workflow ingests MRMS data produced by the National Oceanic and Atmospheric Administration (NOAA), uses NSF Unidata's Local Data Manager (LDM) to transfer and transform the data, and store the resulting datasets on the Jetstream2 object store. The data are then served through the standard interfaces of the NSF Unidata THREDDS Data Server (TDS) allowing users to leverage existing TDS workflows to access these large scientific archives. We plan to transition this workflow into production during the next allocation cycle.
